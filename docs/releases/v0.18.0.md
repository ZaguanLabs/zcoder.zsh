# v0.18.0 — Select the conversation

zcoder.zsh 0.18.0 brings mouse selection into the chat pane. Drag over a reply,
copy the text you need, and keep working without switching to `/copy` or picking
up the sidebar along the way.

This release includes the changes since v0.17.0.

## Select just the chat

With the native UI, **left-click and drag** to select visible chat text. The
highlight stays inside the chat content area, even when the pointer crosses its
borders. **Ctrl+Y** sends the selection to the terminal clipboard; **Escape**
clears it. Kitty has been tested with real pointer input and clipboard reads.
Shift-drag remains the terminal's own, terminal-wide selection gesture.

Copying leaves out chat borders, role labels, code-language labels, and diff
line numbers. Ordinary soft wraps join back together; code indentation and real
line breaks remain. Grapheme-aware boundaries keep supported combining marks
and joined emoji together. Tables retain their displayed layout, and prose
that cannot be mapped safely retains visible line breaks.

The chat view pauses while a selection is active, so streaming cannot move the
text beneath your pointer. Generation and tools continue in the background.
Clearing the selection reveals the new output. Escape clears a selection before
it can stop a running task; press it again to stop. Resizing, scrolling, session
changes, folding, and dialogs clear the selection safely.

Clipboard copying is explicit and uses OSC 52, with no external clipboard tool.
Set `ZCODER_CLIPBOARD=view` for a stable selected-text view if your terminal or
multiplexer blocks clipboard writes. Without a selection, Ctrl+Y and `/copy`
retain the whole-transcript copy view. `ZCODER_MOUSE_SELECTION=false` disables
application selection, and stock curses retains the existing copy workflow.

Selection currently covers the visible viewport. Edge autoscrolling, offscreen
selection, and double-click word selection are outside this release. See
[selection controls and limits](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.18.0/docs/interface.md#select-and-copy-chat-text).

## A more predictable session

- Interactive launches start a fresh job. Use `--resume SESSION_ID` or the sidebar
  to return to an earlier conversation; the exit message includes a resume command.
- Enter submits steering while work runs, and Ctrl+G queues a follow-up. Stopping
  the current turn preserves queued work and an unsent prompt draft, locally and
  through remote connections.
- Search runs with bounded output and a 120-second deadline while input remains
  responsive. Escape timing has regression coverage independent of JSON parsing.
- A simpler footer exposes the current controls. Tabs render as readable spaces;
  the selection footer makes copying, clearing, and the paused view explicit.

## Updated native foundations

**zdraw 0.1.1** supplies the selection component and fixes native builds on Zsh
5.8. It also prevents a drag that started outside selectable text from acquiring
an anchor when repeated press events move into the chat. This release includes
the application integration: rendering, input routing, selection lifetime, and
copying are connected in zcoder itself.

**zjson 0.2.1** strengthens UTF-8 validation and reduces parsing/capture overhead.
zcoder's compatibility checks cover the updated tokenizer and keep trailing
commas rejected by value-consuming APIs. The dependency also offers new
encoding, iteration, and multi-Pointer APIs; their availability is not a claim
that every new API is used by zcoder.

## Upgrade

Stop the running agent, then update a Git checkout:

```sh
git pull --ff-only
git submodule sync --recursive
git submodule update --init --recursive
make native
make compile
```

Restart with your usual command. Rebuilding the native runtime is needed to get
the new chat selection support. Headless and stock-curses deployments can use
`make compile` without building the native runtime. Zsh 5.8 remains the minimum.
