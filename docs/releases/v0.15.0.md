# v0.15.0 — Native Markdown, one-command setup

zcoder.zsh 0.15.0 makes long answers easier to read and the enhanced terminal
interface easier to get running. Markdown tables, nested lists, highlighted
code and clear headings now share a native rendering path powered by **zmdown**
and **zdraw**. A fresh checkout can prepare both with a single `make`.

This release brings together the improvements since v0.14.0, including Unicode
prompt editing, direct shell commands and a more informative terminal interface.

## Clone, make, run

```sh
git clone https://github.com/ZaguanLabs/zcoder.zsh.git
cd zcoder.zsh
make
./zcoder.zsh --model YOUR_MODEL --workspace /path/to/project
```

`make` fetches the pinned submodules, downloads and verifies Zsh 5.9.2, then
builds a private shell and both modules with matching configuration. The normal
launcher selects that runtime automatically. Your system Zsh and login shell
stay unchanged, and no administrator access is needed for the build.

Successful builds are cached. A failed replacement leaves the previous runtime
available, and a build lock prevents concurrent setup in the same checkout.
Build output is recorded in `.build/native/build.log`.

You still need the build tools: Zsh 5.8+, Git, GNU Make, a C compiler, Autoconf,
Autoheader, M4, Patch, wide-character ncurses development headers, Curl, Tar,
Xz, and either `sha256sum` or `shasum`. Missing commands are reported; setup does
not install operating-system packages. See the
[setup guide](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.15.0/docs/getting-started.md#enhanced-curses-module)
for details.

## Markdown that keeps its structure

- **Tables and lists:** aligned tables, nested lists, task lists and quotations
  make detailed replies easier to scan.
- **Useful styling:** headings, emphasis, links and inline code have distinct
  presentation; fenced code keeps the existing syntax highlighting.
- **Streaming and resizing:** layout updates as text arrives and the terminal
  changes size. Copying a reply or transcript preserves the original Markdown.
- **Explicit Unicode handling:** compatible native rows keep grapheme units
  together while clipping. Text that cannot fit native cell storage falls back
  to readable Unicode escapes for that message, without changing saved content.

Rendering uses the system's summed character widths. An emulator's emoji
shaping can still differ from those logical columns. `/terminal` reports the
Markdown backend and any rendering fallbacks.

## More comfortable terminal work

- Prompt arrows, Backspace and Delete respect supported grapheme boundaries,
  keeping combining marks, emoji modifiers, flags and joined emoji together.
- Type `!command` to run a shell command directly. Its output appears in the
  conversation, and the agent waits for your next request before continuing.
- The header shows the workspace's Git branch.
- Native synchronized presentation and expanded `/terminal` diagnostics expose
  drawing capabilities, resource usage and the active input/rendering paths.

## Keep the lightweight path

The Zsh renderer and stock-curses fallback remain available. Skip `make` to use
the installed shell, or set `ZCODER_RUNTIME=system` to bypass an existing private
runtime. `ZCODER_CURSES=stock` and `ZCODER_MARKDOWN=zsh` select the individual
fallbacks.

`make compile` still only compiles application libraries. It does not download
sources or build C code, preserving the existing headless deployment workflow.
Headless server and ACP modes do not load curses.

For an existing Git checkout, stop the agent, run `git pull --ff-only`, then
run `make` for the enhanced interface and restart. Headless deployments can
continue using submodule updates followed by `make compile`.

## Verification and downloads

- All **2,840 tests** pass on the development host, including real terminal
  checks for Markdown, streaming, reflow, retained text and failure handling.
- Automatic setup was tested from a clean clone with no initialized submodules
  or build cache; a second `make` reused the completed build successfully.
- Zsh 5.8 checks cover compilation, fallback rendering and startup handoff to
  the private runtime. This is not a claim that the full suite passes on 5.8.
- Native builds are verified on Linux; BSD/macOS builds still need validation.

The attached **zcoder.zsh-0.15.0.tar.gz** and **zcoder.zsh-0.15.0.zip** contain
the application and both pinned dependency source trees: zdraw `9c599d8` and
zmdown `8bb1390`. **SHA256SUMS** covers both archives. They exclude native
binaries, compiled wordcode and local development data.

Use a Git clone for automatic native setup, which relies on Git's submodule
metadata. The complete source archives support `make compile` and the installed
shell fallback. GitHub's automatic source downloads omit submodule contents.
