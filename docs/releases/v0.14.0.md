# v0.14.0 — A stronger foundation

zcoder.zsh 0.14.0 brings a more responsive terminal interface, preferences that
survive a restart, and stronger protection against overlapping work. It also
improves context estimates without adding model requests or runtime dependencies.

This release gathers the improvements since v0.13.1 and the latest concurrency,
terminal, and token-accounting fixes. Zsh 5.8 remains supported.

## A smoother terminal interface

- **Help closes promptly.** Escape no longer waits through the previous delay;
  `/quit` also avoids unnecessary shutdown latency.
- **Your sidebar choice is remembered.** Toggle it with Ctrl+B, restart the app,
  and keep the layout you chose. Preferences are saved atomically.
- **Clearer Help and faster navigation.** Better section formatting, searchable
  pickers, and slash-command type-ahead make commands and sessions easier to find.
- **Deeper zdraw integration.** Native paste handling, event polling, picker
  widgets, and terminal handoff reduce duplicated TUI machinery while preserving
  the stock-curses fallback.
- **Pasting into a modal stays contained.** On stock curses, a bracketed paste
  can no longer close the modal and leak text into the underlying prompt. Tests
  cover fragmented delimiters, modal ownership changes, and approval dialogs.

## Safer overlapping work

Session saves now detect when another process has changed the session since it
was loaded. A stale writer reports the conflict instead of overwriting newer
work. The unsaved work remains in memory; it is not automatically merged or
persisted, so preserve it before exiting.

Remote cancellation now includes the session and turn IDs once the client has a
receipt. Updated servers reject delayed cancellation requests aimed at different
work. Upgrade both ends to use this protection. Legacy clients and cancellations
before a receipt still use unscoped requests.

## More useful context accounting

- A response without a positive prompt count retains the last usable Ollama
  count and its matching request size, keeping calibration stable.
- `/context` accounts for relay, goal, and loop-recovery guidance, as well as
  custom routing and verifier prompts. The breakdown shares the same prompt
  assembly used for actual requests.
- The inspector labels its calibration sample **Last reported Ollama prompt**.
  Cumulative goal usage still counts only the usage reported for each response.

The next request's token count remains an estimate, with conservative headroom;
this release does not introduce a local tokenizer or additional inference calls.

## Verification

- Zsh 5.9.2: all **2,651 assertions** and **23 visual baselines** pass with the
  bundled renderer; a clean source tree passes all **2,516 assertions** using
  the stock-curses fallback.
- Zsh 5.8: compilation, **37 concurrency assertions**, **36 context-accounting
  assertions**, **83 terminal assertions**, and **96 prompt comparisons** pass.
- Both source archives are checked for matching file contents and privacy
  exclusions, and the extracted source compiles successfully.

The full suite is **not green on the tested Zsh 5.8 installation**. Both this
release and a v0.13.9 baseline encounter asynchronous/PTY failures and a Zsh
segmentation fault in the MCP tests. The focused checks above pass, but the
broader Zsh 5.8 result remains a compatibility investigation, not a full-suite
pass.

Regression tests exercise real competing session writers, cancellation scope,
terminal paste boundaries, and missing model usage reports. The
[concurrency audit](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.14.0/docs/test-gap-audit.md)
and [TUI review](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.14.0/docs/tui-review.md)
document what was tested and the remaining limitations.

## Complete source downloads

The attached **zcoder.zsh-0.14.0.tar.gz** and **zcoder.zsh-0.14.0.zip** include
the pinned zdraw sources at `4bbcc5fd34daa34e28b0f78627a2f42a807e9d79`.
**SHA256SUMS** covers both archives. These packages contain sources, without
prebuilt native modules, Zsh wordcode, local agent instructions, or development
caches. GitHub's automatic source archives omit submodule contents; use the
attached archives for complete sources.

Extract either archive, run `make compile`, and restart. Building the optional
curses module requires a matching Zsh build environment; see the
[development guide](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.14.0/docs/development.md#building-the-curses-dependency).

For an existing checkout on the current repository history, stop the agent and run:

```sh
git pull --ff-only
git submodule sync --recursive
git submodule update --init --recursive
make compile
```

Then restart the agent. Repository history was rewritten during the v0.13.9
privacy cleanup. If your checkout predates that cleanup, use a fresh clone and
transfer any unpublished work separately; do not merge the old history back in.
Local `AGENTS.md` files remain supported and are now ignored by Git.
