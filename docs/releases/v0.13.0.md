# v0.13.0 — A fresh look for native Zsh

zcoder gets a calmer, more readable terminal interface: rounded borders, a
coordinated dark palette, clearer focus styling, and batched transcript drawing.
Inspired by btop's attention to terminal presentation, this release brings that
polish to an interactive coding agent while keeping application logic in Zsh
and screen rendering under curses.

![zcoder.zsh v0.13.0 terminal interface](https://raw.githubusercontent.com/ZaguanLabs/zcoder.zsh/v0.13.0/images/zcoder-0.13.0.png)

## A coordinated interface

Panels, dialogs, syntax highlighting, status messages, and the prompt now share
one palette. Quieter borders frame the transcript; a brighter border identifies
the focused panel. The bundled zcurses module supplies rounded Unicode corners.

Color selection adapts to the initialized curses session:

- **RGB** when the library and terminal description support direct color.
- **256 colors** on ordinary indexed-color terminals.
- **Basic colors or monochrome** when richer modes are unavailable.

Truecolor stays within curses' retained-screen rendering. zcoder does not
rewrite `TERM` or assume that `COLORTERM=truecolor` establishes support. The
256-color palette gives ordinary `xterm-256color` sessions the new appearance
without extra terminal configuration.

## Fewer drawing calls, familiar behavior

Transcript rows can now pass their styled text segments to zcurses in one call,
instead of issuing separate attribute and text calls for every segment. Existing
window caching and synchronized refresh remain in place.

Rows rejected by the span API fall back to the existing renderer, including
combining-character boundaries that cannot be represented as separate spans.
Wrapping and clipping remain in Zsh; general Unicode clipping is separate future
work. Stock curses remains supported, and headless server and ACP modes do not
load the drawing layer.

Use `/terminal` to inspect the palette, borders, span support, RGB state,
color-pair usage, and fallback count. Optional settings are:

| Setting | Behavior |
| --- | --- |
| `ZCODER_COLOR=auto` | Select the supported palette; use `basic` or `mono` to override |
| `ZCODER_BORDERS=plain` | Keep curses' standard borders |
| `ZCODER_SPANS=false` | Use individual transcript drawing calls |
| `ZCODER_CURSES=stock` | Bypass the locally built module |

## Also included since v0.12.1

- Faster large-paste handling, JSON escaping, ranged file reads, and context
  inspection, with bounded context-accounting memory.
- Atomic session-generation publication and reuse of unchanged saved records.
- Stronger JSON, HTTP, ACP, MCP, workspace-search, and approval boundaries.
- Native terminal-size queries through the optional bundled curses module.
- A fix for MCP startup CPU stalls caused by repeatedly scanning growing
  response buffers.

**Upgrading from v0.12.1 or earlier:** stop agents using the session directory
and back it up before upgrading. Sessions migrate on their first save to the
generation format introduced in v0.12.2. Older versions cannot read that format;
preserve the newer directory separately before restoring a backup for downgrade.
See the [v0.12.2 upgrade notes](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.13.0/docs/releases/v0.12.2.md#session-storage-and-upgrade-precautions).

## Source release and verification

The attached `zcoder.zsh-0.13.0.tar.gz` and `.zip` archives include the pinned
zcurses sources at `bc231768168992d71c2e87c7ef55c984cfc5ffb9`. They contain no
prebuilt native modules or Zsh wordcode. `SHA256SUMS` covers both archives.
GitHub's automatically generated source downloads do not include submodule
contents; use the attached archives for the complete source package.

Run `make compile` after extracting. The stock-curses path works without building
the optional module. To enable rounded borders and batching, build with
`ZSH_BUILD_ROOT=/path/to/matching/configured/zsh make curses`, then start a fresh
session. The [development guide](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.13.0/docs/development.md#building-the-curses-dependency)
lists build tools and ABI requirements.

Validation passed 2,193 application checks on Zsh 5.9.2, 2,171 on Zsh 5.8 with
stock curses, and all 22 zcurses module tests. Terminal checks cover batched and
fallback cell equivalence, combining marks, RGB, indexed colors, monochrome,
and stock/bundled modules. The optional native module's tested baseline remains
Zsh 5.9.2; the application retains Zsh 5.8 compatibility through stock curses.
