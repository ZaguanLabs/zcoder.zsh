# v0.16.0 — A smaller core, a calmer terminal

zcoder.zsh 0.16.0 moves its JSON engine into **zjson**, joins the latest
**zdraw** and **zmdown** optimizations, and brings the terminal and remote session
views closer together. The application stays Zsh-first, with less parser code
to maintain and clearer boundaries between reusable libraries and agent behavior.

This release gathers the changes since v0.15.0.

## JSON powered by zjson

The new pinned [zjson](https://github.com/ZaguanLabs/zjson) dependency handles
parsing, quoting, UTF-8 repair, and nested parser contexts in pure Zsh. It needs
no compiler, external JSON executable, or additional native module.

- **446 fewer lines in our JSON library:** `lib/json.zsh` shrinks from 804 to
  358 lines. Ollama codecs and scalar-only tool argument validation stay in
  zcoder, alongside the existing command approval and workspace boundaries.
- **Stricter input validation:** malformed UTF-8 is rejected even in unused
  response fields, and invalid responses cannot publish executable tool calls.
  Parser errors carry structured codes and byte locations.
- **Safe nested parsing:** context accounting, queued input, and remote requests
  preserve the surrounding tokenizer and its diagnostics. Pasted text and older
  cached responses use the public UTF-8 repair API.
- **Zsh 5.8 support:** the library explicitly supports 5.8 and newer, with
  upstream compatibility checks in both C and UTF-8 locales.

In focused local measurements, a synthetic 100-tool MCP catalog parsed about
**2.2× faster**, and Unicode quoting was about **4.3× faster**, than our previous
internal implementation. Raw Unicode parsing still takes about twice as long;
zjson performs strict UTF-8 validation and maintains locale-independent byte
positions. These are individual workload measurements, not overall agent speed.

## A calmer, easier-to-navigate terminal

- Numbered **[1] Sessions** and **[2] Prompt** panels make focus destinations
  visible. **Alt+1** and **Alt+2** jump directly between them; bare digits work
  outside the prompt, while digits typed into a draft remain ordinary text.
- The header groups the project and Git branch after the server, separated by
  `|`, and uses compact `model@server` formatting. Non-repositories no longer
  display “No Git,” and redundant project details are removed from the sidebar.
- Prompt instructions use the surrounding background for a quieter appearance.
- The top-right activity indicator stays steady during tool calls. Its reserved
  space prevents it from overwriting the header, and its brackets remain compact
  and aligned at the right edge.

## The same sessions locally and remotely

The local TUI and remote API now use shared session storage. Sessions created
locally are available through the remote session endpoints, so clients using
the same workspace and profile see the same persisted conversations. Existing
workspace/profile boundaries, stale-writer protection, and session locking remain
in place.

## Faster Markdown and drawing

Updated zdraw and zmdown pins improve text measurement, styled rows, Unicode
lookup, table fitting, and Markdown span generation. The application already
uses these paths; no new setting is needed.

Across the tested prose, Unicode, fenced-code, and table fixtures, span generation
was **2.15–4.43× faster**, while complete transcript layout took about **5–8% less
time**. Exported layout and retained-cell snapshots stayed identical. See the
[native performance report](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.16.0/docs/native-performance-update.md)
for workloads, methodology, and limits.

## Setup and development

`make` initializes all three pinned dependencies and prepares the enhanced UI.
`make compile` initializes zjson when missing and compiles the application and
zjson libraries without downloading or building C code. Complete source checkouts
can recompile offline, and setup preserves local dependency edits.

The default build no longer repeats the syntax-check pass. `make test-fast`
provides a shorter development loop, with omitted integration groups reported
explicitly; `make test` remains the complete check before handoff. Optional
`--timings` output helps identify expensive groups.

## Upgrade

For a Git checkout, stop the running agent, then:

```sh
git pull --ff-only
git submodule sync --recursive
git submodule update --init --recursive
make
./zcoder.zsh --model YOUR_MODEL --workspace /path/to/project
```

Use **`make compile` instead of `make`** for a headless deployment or the stock
renderer. Restart the agent after updating. Native setup still needs the
[documented build tools](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.16.0/docs/getting-started.md#enhanced-curses-module);
it does not install system packages or replace your login shell.

JSON setup, offline recompilation, and dependency-edit protection. The upstream
zjson suite also passed **14,130 checks per run** on Zsh 5.8 and 5.9.2 in both
locales. Native build validation is on Linux; BSD/macOS builds remain unverified.
