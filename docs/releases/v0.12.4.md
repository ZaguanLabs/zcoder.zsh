# v0.12.4 — Optional native curses geometry and feature discovery

The enhanced ZaguanLabs curses module is pinned as a Git submodule at
`vendor/zcurses`, using public HTTPS. Build it with `make curses` against a
configured Zsh source tree matching the installed shell to enable automatic
local loading. Standard installs retain the stock curses fallback, and headless
server and ACP startup remain independent of curses.

Native geometry removes `stty size` subprocesses from resize polling. The new
`zcurses_features` array selects the backend before the first terminal query;
transient failures preserve native selection and retry at the next poll.
Older modules retain the one-time compatibility probe. `/terminal` now reports
the module backend, compiled features, and resize-query backend.

The local build stamp checks shell version, patch level, platform, and host to
avoid automatically selecting a binary copied to another farm machine. It is
not a universal ABI guarantee. The module's tested baseline is Zsh 5.9.2;
Zsh 5.8 remains the application target with the stock-module fallback.

Existing checkouts can initialize and synchronize the dependency with:

```sh
git submodule sync --recursive
git submodule update --init --recursive
```

The development guide documents builds and compatibility, and a separate
feature-request document records proposed future curses improvements.

Validation covers module loading and fallback, feature discovery, transient
geometry failures, repeated resizing and UI re-entry, and headless startup.
Run `make test` and `make compile` after updating. Rebuild native modules and
wordcode with the destination host's matching Zsh where needed.
