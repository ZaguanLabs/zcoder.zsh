# v0.19.0 — Stronger checkpoints, smaller core

zcoder.zsh 0.19.0 makes long-running local-agent sessions more dependable.
Compaction now produces tighter handoffs, recognizes when Ollama runs out of
generation room, and has a safe way forward when a model cannot finish strict
JSON. The release also breaks several large runtime files into focused modules
without changing the native-Zsh deployment model.

This release includes the changes since v0.18.0.

## Compaction that finishes

The compaction prompt now follows Codex's context-checkpoint handoff structure:
preserve progress and decisions, keep durable constraints and user preferences,
identify the exact interruption point, and make the next actions immediately
usable. zcoder adds strict limits around that contract—four short entries per
section, bounded item lengths, and an explicit instruction not to repeat broad
project, file, or tool inventories.

That tighter prompt addresses the failure seen in real local-model sessions:
the model could spend its complete 2,048-token compaction allowance repeating
context and then stop inside a JSON string. zcoder now reads Ollama's
`done_reason`; an output-limit response skips corrective JSON retries and makes
one final request for a concise plain-text handoff. The same fallback follows
exhausted structured retries. Empty output, fences, JSON fragments, and other
non-handoffs still fail closed, and exact conversation history is replaced only
after a usable checkpoint passes validation and yields enough context space.

Complete JSON surrounded by commentary or a Markdown fence can now be recovered
before checkpoint validation. Truncated JSON is never guessed or repaired.

## Strict JSON, friendlier model boundaries

`zjson` remains a strict general-purpose parser. Model quirks are handled in
zcoder's application layer instead:

- One complete, independently valid object can be extracted from model prose or
  a code fence.
- Ollama tool arguments encoded as a JSON string are normalized back to an
  object before dispatch.
- The native scanner understands strings and escapes, has a hard size bound,
  and rejects incomplete or ambiguous multiple objects.
- Rejected responses publish no partial tool calls.

This accepts common model serialization mistakes without making malformed or
truncated input executable.

## Better temporal context

Every normal, routing, and verifier system prompt now ends with a stable local
date and time. Context accounting uses the exact same assembled prompt, so the
inspector continues to match what Ollama receives.

## A smaller, clearer runtime

The agent loop, prompt assembly, LFM normalization, command dispatch, command
safety, TUI control, and remote client/server responsibilities now live in
focused modules. The remote transport split separates client behavior, server
protocol handling, and server-side agent execution. Interactive command and TUI
logic have likewise moved out of the entrypoint.

These are structural changes rather than new dependencies: zcoder remains a
Zsh-first application, retains Zsh 5.8 compatibility, and keeps tool dispatch
separate from curses and Ollama.

## Upgrade

Stop the running agent, then update a Git checkout:

```sh
git pull --ff-only
git submodule sync --recursive
git submodule update --init --recursive
make compile
```

Restart with your usual launcher.
