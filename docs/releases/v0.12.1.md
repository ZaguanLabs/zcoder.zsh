# v0.12.1 — Steering, queued follow-ups, and a clearer conversation

v0.12.1 is the first published source release of the 0.12 series. It includes
the steering and queued-input features introduced in v0.12.0, the terminal
improvements since the last published release (v0.11.1), and v0.12.1's grouped
assistant responses.

## Steer work and queue the next task

- Press Enter during an active turn to send a correction after the current
  response and its complete tool batch. Press Ctrl+G to queue a follow-up that
  starts after the current task finishes.
- Accepted messages are saved with stable IDs. After cancellation, an error,
  or a process restart, inspect and recover unconsumed input with `/queue`,
  `/queue resume`, and `/queue drop ID`.
- Recovery checks saved history before consuming a message again, preventing
  duplicate user entries after an interrupted receipt write.
- Remote HTTP servers expose optional input-queue endpoints, and ACP exposes
  the namespaced `_zcoder/input` extension. Both protocols remain at version 1;
  clients discover queue support through capability flags.

See the [steering and queued-input guide](https://github.com/ZaguanLabs/zcoder.zsh/blob/v0.12.1/docs/queued-input.md)
for delivery rules, recovery, and client integration.

## A clearer, more responsive terminal

- Consecutive assistant responses and their intervening tool activity now form
  one conversation block, with a single Assistant heading. Collapsing that
  block hides its continuations and tools; reasoning remains independently
  foldable. The plain-text copy view follows the same grouping.
- Tool entries show their state and readable labels with relative file paths.
  Transcript selection and folding make long conversations easier to inspect.
- A command palette, context inspector, shared modal controls, prioritized
  status notices, and activity indicators expose commands and current work.
- Local Ollama responses stream through the shared activity loop. Command,
  search, patch, MCP, remote, model-discovery, and context-discovery waits keep
  the interface responsive to input and cancellation.
- Changed-window rendering and incremental transcript layout reduce repeated
  redraws. Synchronized terminal updates are detected where supported, with
  diagnostics and fallback behavior documented in the interface guide.
- The TUI name/version header is restored, and assistant headings no longer
  repeat the model already shown at the top.

## Fixes and other changes

- Streamed JSON Unicode escapes are parsed correctly.
- Context accounting includes retained reasoning, live reasoning, and Skill
  resources.
- Headless server startup avoids loading terminal and delegate runtimes.
- The Antigravity consultant and worker default to `gemini-3.8-flash-high`,
  configurable through `ZCODER_AGY_MODEL` (introduced in v0.11.2).
- Regression coverage now includes real local and remote TUI entrypoints in
  PTYs, queued-input recovery and HTTP/ACP admission, cancellation during
  background work, and grouped transcript rendering and navigation.

## Install or upgrade

Download and unpack a source archive from this release, then run:

```sh
./zcoder.zsh --version
./zcoder.zsh --model YOUR_OLLAMA_MODEL --workspace /path/to/project
```

Zsh 5.8 or newer remains required. Local model execution needs Ollama and a
tool-capable model; search uses `rg`, and patching uses `git` or `patch`.
Optional `make compile` builds wordcode locally. Source archives omit generated
wordcode and do not require a build step to run.

Queued input adds no runtime dependency. Steering waits for a complete tool
batch and preserves command-approval rules. Older remote and ACP clients can
continue using the existing turn, approval, and event contracts; they need
support for the optional extensions to submit queued input.

Review the [changes since v0.11.1](https://github.com/ZaguanLabs/zcoder.zsh/compare/v0.11.1...v0.12.1).
