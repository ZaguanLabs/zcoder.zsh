# v0.17.0 — Cleaner discovery, clearer edits

zcoder.zsh 0.17.0 makes everyday coding sessions easier to follow: file discovery
skips hidden clutter, edit tools have clearer jobs, and successful changes open
their diffs in the transcript. Remote connections stay responsive while clients
or Ollama are slow, and compaction gives the model a more precise place to resume.

This release gathers the changes since v0.16.0.

## Find the source, skip the clutter

`list_files` no longer enables ripgrep's hidden-file traversal. Hidden files and
directory trees are skipped by default, so they cannot crowd visible source files
out of a bounded listing. Root and nested `.gitignore` rules continue to apply,
including outside Git repositories.

An explicitly requested hidden or ignored directory can still be listed, and
ignore-file negations can make hidden entries visible. These exceptions are now
documented alongside the default behavior.

## Choose the edit that fits

- **`replace_text`** handles one contiguous change in one existing file, including
  a multiline block or function. The old text must match exactly and uniquely.
- **`apply_patch`** handles several separated changes or changes spanning files,
  using a standard unified diff.
- **`write_file`** creates a file or deliberately replaces its complete contents.

The tool descriptions and coding prompt use the same distinction. Replacement
fragments should stay focused, with enough context to identify the target, rather
than absorbing large unchanged regions to combine separated edits.

Successful replacements and patches automatically open an inline diff preview.
Line numbers, additions, and removals remain visible in saved sessions and remote
connections; plus and minus markers keep changes readable in monochrome.

## Keep the session moving

Remote servers handle partial requests and stalled response readers without
making the listener wait for each connection to finish. Authentication is checked
before waiting for the remaining request body, and connection deadlines bound
stalled work. Ollama model-residency checks and context refreshes also run outside
the listener. Turns and approval decisions retain their existing ordering.

Compaction checkpoints emphasize completed edits, observed verification, and the
next unfinished action. A saved continuation cue reminds the model that the
workspace still exists and work should resume from that point.

File reads also have a clearer contract: `read_file` returns a complete file or
an explicit size error; `read_file_range` requires an inclusive line range.
The prompt discourages duplicate reads and unnecessary discovery after successful
verification.

## A clearer terminal, locally and remotely

The shared palette adapts to the terminal's available colors. Automatic color
selection respects `NO_COLOR`, while explicit basic mode retains ANSI status
colors. Remote connections use warmer surfaces, lavender accents, and a visible
`REMOTE` label that remains identifiable in monochrome.

## Upgrade

Stop the running agent, then update a Git checkout:

```sh
git pull --ff-only
git submodule sync --recursive
git submodule update --init --recursive
make compile
```

Restart the agent with its usual launch command. Use `make` when preparing the
enhanced native UI; headless deployments can use `make compile`.
