# zcoder.zsh v0.11.0

v0.11.0 makes zcoder available as an Agent Client Protocol v1 agent, adds an
experimental authority-aware routing stage, and hardens conversation
compaction across model families. It also documents the remote protocol in
enough detail for independent implementations and records the design boundary
for future HTTPS, WebSocket, and external-runtime integrations.

## Highlights

### Use zcoder from ACP clients

- `./zcoder.zsh --acp` starts a newline-delimited JSON-RPC stdio agent for ACP
  clients such as Zed. The adapter reuses the normal Ollama, session, tool,
  workspace, Skills, MCP, and approval machinery instead of creating a second
  agent runtime.
- Protocol v1 initialization, `session/new`, `session/load`, `session/prompt`,
  and `session/cancel` are supported, including history replay and concurrent
  cancellation while a prompt worker is active.
- ACP clients receive assistant text, private reasoning, tool lifecycle
  updates, and permission requests for commands and external actions.
- Text, resource links, embedded text resources, and client-forwarded stdio MCP
  servers are accepted in direct local mode. Unsupported image, audio,
  filesystem, and terminal capabilities are not advertised.
- `--acp --connect HOST` bridges an ACP client to an existing authenticated
  zcoder remote server. The server workspace remains authoritative even when
  client and server filesystem paths differ.

### Route authority before exposing tools

- Experimental `--tool-exposure staged` begins ordinary user turns with a
  small structured decision: respond directly, admit workspace capabilities,
  or admit explicitly requested external-write capabilities.
- The routing request exposes no executable tool channel. Direct answers avoid
  loading the full tool catalog, while workspace and external decisions enter
  the established agent loop with the appropriate capability boundary.
- External MCP mutations remain separately confirmed at dispatch. Staged
  routing does not weaken workspace confinement, shell-command approval, or
  the rule that model tool selection is not user authority for an external
  action.
- Tool-effect metadata, prompt guidance, UI labels, and behavioral evaluation
  cases now agree on the distinction between read-only inspection, workspace
  work, and externally visible writes.

### Model-neutral compaction

- Compaction now supplies its checkpoint contract through Ollama's JSON Schema
  `format`, constraining output at the server rather than relying on one model
  family to follow prose formatting instructions.
- Compaction requests omit callable tools, removing a competing output channel
  for models that strongly prefer tool calls whenever definitions are present.
- The textual contract now states every field type unambiguously and requires
  empty arrays to remain arrays rather than becoming strings or null values.
- Local validation remains authoritative before exact history can be replaced.
  Rejections identify the mistyped field, and corrective prompts include a
  distinct attempt number and the full type contract so temperature-zero
  retries are not identical.
- Failed compaction still preserves the original conversation and checkpoint
  state exactly.

### Protocol and runtime references

- The ACP integration reference specifies JSON-RPC framing, initialization,
  sessions, prompt content, updates, permissions, cancellation, MCP forwarding,
  remote bridging, and the requirements for a custom harness.
- The remote-access specification documents the core protocol-1 baseline end
  to end: bearer authentication, readiness, turns, event cursors, approvals,
  cancellation, session persistence, state machines, failure behavior,
  security constraints, and conformance scenarios. The ACP reference covers
  the newer opt-in structured tool-event extension.
- A libcurl bridge design defines a possible bounded helper or loadable-module
  boundary for HTTPS, streaming HTTP, and WebSockets without moving zcoder's
  policy engine out of Zsh.
- External-runtime research compares Codex, Claude, and Antigravity integration
  surfaces and proposes a provider-neutral process protocol. These transport
  and runtime documents are implementation guidance, not claims that the
  proposed integrations ship in v0.11.0.

### Interface, tests, and compatibility

- The project README now includes a current terminal-interface screenshot and
  direct entry points for ACP and remote operation.
- The native Zsh suite now contains 1,000 tests covering ACP framing and
  lifecycle, remote structured tool events, staged capability routing,
  external-write confirmation, compaction schemas and recovery, persistent
  sessions, workspace confinement, MCP, relays, goals, and curses rendering.
- Zsh 5.8 or newer remains supported. `make compile` continues to produce
  optional compatible wordcode without adding a runtime dependency.
- Default full tool exposure remains available. Existing terminal sessions,
  remote protocol-1 clients, MCP configuration, goals, relays, and external
  delegate commands remain compatible.
