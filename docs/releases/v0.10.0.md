# zcoder.zsh v0.10.0

v0.10.0 makes long-running work verifiable and installed Skills meaningfully
discoverable. Persistent goals now require an independent completion check,
while a bounded Skill routing catalog lets the model recognize relevant
capabilities without waiting for the user to name them. The release also
strengthens project-instruction compliance, compaction recovery, local-agent
replies, and MCP diagnostics.

## Highlights

### Persistent goals with independent verification

- `/goal OBJECTIVE` starts a durable objective that survives session saves and
  compaction. `/goal --tokens N OBJECTIVE` can also apply a cumulative model
  token budget.
- Goal work cannot complete on the worker model's assertion alone. A separate,
  read-only verifier receives the objective and current evidence, then accepts
  the result or returns focused feedback for another work cycle.
- Goal state records candidate attempts, verifier rejections, and cumulative
  prompt-plus-output usage. `/goal status`, `/goal pause`, `/goal resume`, and
  `/goal clear` expose explicit lifecycle control.
- Interrupted goals reopen as paused rather than silently resuming mutations.
  Remote clients negotiate goal support and retain the server-owned lifecycle.
- Loop, transport, compaction, cancellation, and repeated-verifier-failure
  guards remain authoritative; a token budget limits usage but never converts
  incomplete work into success.

### Skills that models can actually find

- Skill names and sanitized descriptions now remain visible in a bounded
  routing catalog. A task that clearly matches a description must activate that
  Skill before the model performs the matching work.
- Full `SKILL.md` bodies are still loaded progressively, so recurring context
  pays for routing metadata rather than every installed instruction set.
- `discover_skills` appears only when the visible catalog is byte-truncated.
  Omitted descriptions remain searchable within the separately bounded
  discoverable set, while Skills outside that set cannot be activated by the
  model.
- Active Skill resources retain their canonicalized read-only boundary, and
  Skill metadata cannot relax workspace, project, safety, or command-approval
  policy.
- Real-model evaluation now includes both an implicit Skill match and a
  non-match precision case, making routing regressions measurable.

### More reliable instructions and context recovery

- Project instructions are framed as mandatory requirements at the beginning
  and completion boundary of each turn. The model is told to check for more
  specific nested guidance before changing deeper files.
- The behavioral evaluation suite now tests first-action project-instruction
  compliance in addition to checking final output.
- Compaction uses a bounded cutoff search, validates the checkpoint yield, and
  retries malformed checkpoints and transient transport failures without
  corrupting the original history.
- Failed or low-yield compaction restores exact prior state. Successful
  compaction preserves recent user corrections, tool-call ownership, and the
  stable system/tool prefix.

### Safer local coordination and clearer MCP status

- A relay-originated turn may reply directly to its exact sender. It cannot
  forward to a third agent, and the existing acknowledgement still means
  accepted for delivery rather than completed.
- MCP status output now aligns consistently and retains negotiated transport,
  scope, protocol, and connection details.

### Tests and compatibility

- The native Zsh suite now contains 889 tests covering persistent goal loops,
  independent verification, Skill routing and truncation, project guidance,
  compaction recovery, relay reply authority, MCP behavior, workspace
  confinement, and the TUI.
- Zsh 5.8 or newer remains supported.
- Ollama still needs a model with native tool-calling support.
- Existing sessions, non-goal conversations, MCP configuration, remote
  protocol-1 clients, and external harness commands remain compatible.
- `make compile` can regenerate optional local `.zwc` wordcode after updating;
  compilation remains an optimization rather than a requirement.
