# zcoder.zsh v0.9.0

v0.9.0 lets local zcoder instances coordinate without turning zcoder into a
distributed orchestration framework. It also makes smaller local models more
dependable, cuts recurring context overhead, and gives long-running sessions a
safer compaction path.

## Highlights

### Hand work to another local agent

- Interactive instances owned by the same operating-system user can discover
  each other on the same machine with `/list-agents`.
- A user can explicitly ask the current model to contact one exact instance.
  The new `list_agents` and `send_agent_message` tools deliver a concise task
  through a private Unix-domain socket relay.
- `/agents` reports the local relay state and queue depth. `/agents pause` and
  `/agents resume` reject or resume new deliveries without losing work that was
  already accepted.
- A background listener can accept and queue messages while the receiving
  agent is busy, but it never touches Ollama, tools, curses, or session state.
  The foreground TUI remains the only path that starts an agent turn.
- Relayed work appears with a distinct transcript role and enters the target's
  normal agent loop. The target keeps its own workspace boundary, project
  instructions, profile, command approvals, cancellation, and verification
  requirements.
- Delivery acknowledgements mean queued, not completed. Relayed turns cannot
  call `send_agent_message`, preventing implicit forwarding chains and
  model-created agent swarms.

The first relay release is deliberately local: no TCP, SSH, remote-client
bridge, broadcast, completion callback, or persistence across receiver
shutdown. Set `ZCODER_RELAY=off` to disable it, or start paused with
`ZCODER_RELAY=paused`.

### Sharper behavior from smaller local models

- LFM-family models are now held to Ollama's native `tool_calls` channel.
  Planner-shaped JSON in assistant content is classified only for a corrective
  retry and is never converted into an executable action.
- Native tool calls remain authoritative when a model emits competing content.
  Incidental plans and `<think>` blocks move into private, collapsible
  reasoning instead of leaking into the final response.
- Recovery now catches dangling tool markers, malformed planner envelopes,
  false claims that tools are unavailable, and file-absence conclusions drawn
  from content search rather than path discovery.
- The focused edit path is clearer: `replace_text` handles one exact unique
  replacement, while `apply_patch` uses one canonical unified-diff contract.
  Repeated rejected LFM patches stop after a bounded correction budget.
- Read and MCP results remain available to the model without flooding the
  transcript. MCP calls show a concise, terminal-safe activity label instead.

### More context for the work, less context for catalogs

- Agent Skills are discovered by focused query and activated on demand. The
  complete catalog no longer rides along in every model request, while active
  Skill instructions still survive compaction.
- Compaction checkpoints are schema-validated JSON. They preserve the initial
  request and latest correction, keep tool results attached to their owning
  assistant call, and reject checkpoints that save too little context.
- Normal output has an explicit 8,192-token default ceiling. Automatic
  compaction reserves that allowance when deciding when to run, improving
  behavior at the supported 32K context floor.
- `/context` now reports an estimated component-level context bill across base
  guidance, project instructions, Skills, MCP, checkpoints, tool schemas, and
  conversation roles.

### Better evaluation and regression coverage

- Real-model evaluation can select scenario subsets, retain transcripts and
  JSONL histories, and report timing alongside tool, retry, loop, and token
  metrics.
- The shell suite now contains 827 tests, including real two-process relay
  delivery, exact target discovery, Unicode and multiline payloads,
  pause/resume state, origin isolation, listener cleanup, local-model recovery,
  context accounting, and compaction boundaries.

## Compatibility and upgrade notes

- Zsh 5.8 or newer remains supported.
- Ollama still needs a model with native tool-calling support.
- Existing sessions, MCP configuration, remote protocol, and external harness
  commands remain compatible.
- The relay starts only for local interactive sessions. One-shot, remote-client,
  and remote-server processes do not publish themselves as peers.
- Public relay manifests contain workspace, model, profile, PID, and session
  metadata, but live in a same-user directory that must deny group and other
  access. Sender metadata is useful context, not cryptographic identity.

After updating, `make compile` can regenerate optional local `.zwc` wordcode.
Compilation is an optimization and is not required for correctness.

See the [inter-agent communication guide](../inter-agent-communication.md) for
the complete relay protocol and safety model, or review the
[full v0.8.0...v0.9.0 change set](https://github.com/ZaguanLabs/zcoder.zsh/compare/v0.8.0...v0.9.0).
