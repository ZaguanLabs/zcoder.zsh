# v0.12.2 — Native Zsh performance and reliability

v0.12.2 reduces pauses during large pastes, context inspection, JSON encoding,
and ranged file reads. It also tightens protocol and approval handling and
changes session saves to publish complete snapshots with less repeated writing.

## Faster local work

Targeted measurements on the development machine showed:

| Operation | Before | After |
| --- | ---: | ---: |
| Decode a 100,000-character paste | 16.7 s | 1.34 s |
| Inspect 1,000 history messages with a warm accounting cache | 591 ms | 30 ms |
| Encode 32,768 Unicode characters followed by DEL as JSON | 42 s | 9 ms |
| Read the first line of a 10 MB file | 188 ms | 1 ms |

These are local fixture measurements, not promises about terminal rendering,
Ollama inference, or another machine. `make benchmark` provides repeatable,
opt-in measurements with three warmups and five samples per case; see
[Development](../development.md#performance-measurements).

Paste decoding uses bounded chunks. Context inspection reuses accounting for
unchanged messages and the prepared tool catalog, without starting MCP discovery.
JSON escaping uses native split/join operations for uncommon controls as well as
common escapes. Ranged reads skip preceding lines in blocks and retain bounded
head-and-tail output. A single selected, exceptionally long line is still
assembled in memory before output truncation.

Terminal wrapping, clipping, padding, and cursor placement account for display
cells, including wide characters and combining marks. Complex emoji sequences
can still have terminal-dependent shaping and width.

## Protocol and safety fixes

- Search and file listing disable inherited ripgrep configuration and symlink
  following. A configured `--follow` can no longer expose outside files, and a
  configured `--pre` cannot run a program through the search tool.
- A workspace of `/` correctly admits its descendants. Ranged reads no longer
  invent an extra blank line after a final newline.
- JSON parsers reject malformed numbers, trailing commas, forbidden literal
  controls, and trailing content. Intentional replacement of unpaired Unicode
  surrogates remains supported; DEL remains valid literal JSON text.
- Buffered chunked HTTP requires complete framing, including chunk terminators
  and the final zero chunk.
- ACP buffers partial input and worker frames, so receiving some bytes does not
  block the broker waiting for a whole line. Permission responses must match
  the outstanding request and session; session-wide command approval is accepted
  only when that option was offered.
- MCP matches top-level JSON-RPC IDs and methods, rather than similarly named
  fields inside a result. Partial responses remain subject to the deadline;
  uncertain failed exchanges disconnect the broker instead of reusing it.
- Strict completion and active goals cannot become ordinary tool-free success
  when `ZCODER_INCOMPLETE_RETRY_LIMIT=0`. Zero permits no recovery attempts; it
  does not waive the required `finish` or goal verification.

Read framing improves responsiveness but does not make every network or pipe
write asynchronous. Command and external-action approval policies remain in
force.

## Session storage and upgrade precautions

Saves now write immutable records and a generation manifest, then atomically
replace the session's `current` file to publish that generation. Unchanged
records can be referenced from an earlier generation. A writer lock serializes
publication, and shared reader leases keep a loaded snapshot safe from
collection. After more than 32 manifest generations accumulate, collection
retains the current and previous manifests and every record either references.
Referenced records may therefore remain in older generation directories.

Existing legacy sessions remain readable. Their first save in this release
migrates into the generation format while preserving the legacy files. Checked
writes and atomic publication protect the committed snapshot from an interrupted
process; this is not an `fsync` guarantee against power loss.

**Back up the session directory before upgrading.** By default it is
`$ZCODER_HOME/sessions`; an explicit `ZCODER_SESSIONS_DIR` overrides that path.
Stop agents using that directory before taking the backup or switching versions.
An older binary cannot read the new generation format. Restoring a legacy backup
for a downgrade loses work saved after that backup, so preserve a separate copy
of the newer session directory before restoring. There is no automatic downgrade
or conversion of newer work into the legacy format.

Zsh 5.8 or newer remains the runtime target. Run `make test` and `make compile`
after updating. Compilation uses the installed Zsh; compiling successfully with
a newer version does not verify execution on Zsh 5.8. Source can run without
precompiled wordcode, and generated `.zwc` files should be rebuilt locally.
