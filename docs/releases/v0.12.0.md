# v0.12.0 — Steering and queued follow-ups

Send a correction while zcoder works with Enter, or queue a later task with
Ctrl+G. Steering joins the conversation after the current response and complete
tool batch. Follow-ups wait for task completion.

Accepted input is saved with stable IDs. Cancelled or interrupted work leaves
unconsumed messages available through `/queue`, `/queue resume`, and
`/queue drop ID`. Recovery avoids appending a user message twice if a process
dies between saving history and writing its consumption receipt.

Remote servers advertise optional input endpoints, and ACP exposes a
namespaced `_zcoder/input` extension. Both protocol versions remain 1.
Existing turn, approval, and event contracts remain available to older clients.
See the [queued-input guide](../queued-input.md) for client integration.

This release also restores the TUI name/version header and readable tool labels
with relative file paths, fixes streamed JSON Unicode-escape parsing, and
includes retained reasoning, live reasoning, and Skill resources in context
accounting.
