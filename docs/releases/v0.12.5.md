# v0.12.5 — Fix MCP startup CPU spikes

Consuming a large MCP response now slices the receive buffer at the known
newline boundary. The previous shortest-prefix pattern removal repeatedly
matched a growing prefix, pinning a core during startup tool discovery.
Replaying the captured 51 KB response fell from 5.35 seconds to 16–17 ms;
tool discovery during a fresh launch fell from about 5.6 seconds to 0.29 seconds.

The native JSON scanner also skips text spans through array searches when the
optional PCRE accelerator is unavailable or cannot match a value. A 50 KB
fallback scan fell from about 2.6 seconds to 49 ms.

Regression coverage includes large Unicode frames, coalesced responses,
incomplete buffered tails, escapes, nested routing fields, and unterminated
values. Run `make test` and `make compile` after updating.
