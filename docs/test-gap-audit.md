# Test gap audit: overlapping operations

Audited v0.13.8 on 2026-09-10. This was a focused audit of persistence,
cancellation, and terminal ownership, not a coverage measurement or a claim
that all races have been eliminated.

## Confirmed bugs and regression tests

### An older writer could replace newer session history

Two processes started with the same committed history. One appended a response
and saved successfully. The other then saved its older view. Both acquired the
exclusive save lock correctly, but the second save replaced the first response.

The existing transaction tests covered failed writes, interruption before and
after publication, immutable records, and collection. They did not exercise a
second process publishing between another process's load and save.

`state_save_session` now checks the generation last observed by the process
against the current generation while holding the write lock. A mismatch rejects
the save and preserves the newer commit. This observation is independent of the
append cache, so loading a session with an unavailable skill cannot bypass it.

[Concurrency tests](../tests/concurrency.zsh) fork an actual second Zsh writer,
check that its response survives a stale save, verify that rejected saves retain
in-memory work, and exercise an explicit reload followed by another append.
They repeat the conflict after a missing skill invalidates the append cache.

This is conflict detection, not automatic merging. Rejected work remains in
memory and is not durable. Preserve any unsaved text before exiting the stale
instance. The loader's explicit no-save reload path is covered by the test;
there is no new interactive merge or conflict-resolution command.

### A delayed cancellation could stop a different turn

The client sent `{}` to `/v1/cancel`. The server did not inspect the request body
and cancelled whichever turn was current. A late request for turn A could
therefore remove turn B's pending prompt and close B's input admission.

Clients now include `session_id` and `turn_id` when they have a turn receipt.
The server rejects mismatches with HTTP 409. Incomplete or wrongly typed scopes,
malformed JSON, and nonempty requests without a scope receive HTTP 400 before
cancellation is invoked.
An exact match still cancels the intended work.

The regression tests exercise the server dispatcher and real pending-prompt
cancellation, with transport and event output replaced by controlled adapters.
They verify prompt preservation, untouched input admission, request validation,
matching cancellation, and the body generated by the client. They do not
simulate two live network clients racing over a socket.

Legacy `{}` cancellation remains supported, including an interrupted submission
before a receipt arrives. That path is still unscoped. Older servers also do not
enforce the new scope. Closing that remaining race requires a submission
identity known before sending the request and a compatible protocol transition.

## Other evidence reviewed

| Area | Existing evidence | Limit of this pass |
| --- | --- | --- |
| Session transactions | `hardening_state.zsh` injects write failures and SIGKILL around publication and checks collection | No physical disk-full or power-loss durability experiment |
| Terminal ownership | `handoff.zsh` covers failed suspend/resume, fallback rebuilding, and real PTY termination during copy view | No additional handoff bug reproduced; actual terminal emulators and slow SSH links were not swept |
| Protocol progress | `hardening_protocol.zsh` checks partial ACP/MCP frames and request-bound permissions; remote wait tests cover cancellation acknowledgements | No exhaustive scheduler interleaving exploration |
| Concurrent preferences | Preference tests cover restart, atomic publication failure, and retaining a process's choice through curses re-entry | No stress test with many simultaneously writing TUIs |

The next useful investigations are cancellation before a turn receipt,
shutdown while a relay peer holds an incomplete frame open, and overlapping
workers modifying the same workspace. Detecting stale session saves does not
serialize tool side effects or establish a single worker owner for a session.

## Verification

The new reproductions failed against the pre-fix code. All 37 new assertions
pass with the fixes, both locally and with Zsh 5.8 in an isolated temporary
copy of the sources. The full local `make test`
passes 2,617 assertions and its 23 retained-cell visual baselines.
`make compile` passes. The full suite was not rerun on every farm host.
